# Food Delivery API — тренажёр для контента

> **Назначение:** Демо-API для YouTube/Instagram контента. Не дублирует Practicum, но содержит похожие баги.
> **Архитектура:** один в один как Practicum — Express.js + PostgreSQL (или SQLite), v1 (баги) / v2 (фиксы).
> **Тема:** Доставка продуктов/еды.
> **Порт (план):** Timeweb, `85.193.81.51:3003` (или отдельный домен).

---

## Сущности и методы (~17 эндпоинтов)

### 1. Рестораны / Магазины (`/stores`)

| Метод | Эндпоинт | Описание |
|-------|----------|----------|
| GET | `/stores` | Список магазинов (+фильтры по типу кухни/району) |
| GET | `/stores/:id` | Детально + меню |
| POST | `/stores` | Добавить |
| PATCH | `/stores/:id` | Обновить |
| DELETE | `/stores/:id` | Удалить (только если нет активных заказов) |

### 2. Меню и товары (`/products`)

| Метод | Эндпоинт | Описание |
|-------|----------|----------|
| GET | `/stores/:id/products` | Товары магазина (+фильтры по категории) |
| POST | `/stores/:id/products` | Добавить товар |
| PATCH | `/products/:id` | Изменить цену/описание |
| DELETE | `/products/:id` | Убрать товар |

### 3. Корзина (`/cart`)

| Метод | Эндпоинт | Описание |
|-------|----------|----------|
| GET | `/cart` | Моя корзина |
| POST | `/cart` | Добавить товар (+ quantity) |
| PATCH | `/cart/:item` | Изменить количество |
| DELETE | `/cart/:item` | Удалить позицию |

### 4. Заказы (`/orders`)

| Метод | Эндпоинт | Описание |
|-------|----------|----------|
| POST | `/orders` | Оформить (из корзины, адрес доставки) |
| GET | `/orders` | Мои заказы (+статус) |
| GET | `/orders/:id` | Детали заказа |
| PATCH | `/orders/:id/cancel` | Отменить (если статус pending) |

### 5. Доставка (`/delivery`)

| Метод | Эндпоинт | Описание |
|-------|----------|----------|
| GET | `/orders/:id/delivery` | Статус доставки (+ курьер) |
| PATCH | `/orders/:id/delivery/assign` | Назначить курьера |

## Баги, похожие на Practicum (но не дублирующие)

### Категория: Валидация (как в Practicum — нет валидации name)

| # | Баг | Practicum аналог | Чем отличается |
|---|-----|------------------|----------------|
| B1 | **POST /orders — пустой адрес проходит** | Practicum: POST без тела → `success:true` | Здесь: адрес не проверяется совсем, заказ без адреса проходит успешно |
| B2 | **POST /cart — quantity = -1 → успех** | Practicum: age < 0 → 500 | Здесь: отрицательное количество, но нет ошибки, сумма уходит в минус |
| B3 | **POST /stores — пустое название магазина** | Practicum: name принимает цифры и символы | Здесь: название пустое, но магазин создаётся |
| B4 | **PATCH /products — цена = 0 → 200 OK** | Practicum: PATCH с age строкой | Здесь: бесплатный товар, цена 0 проходит валидацию |

### Категория: Логика (как в Practicum — DELETE не удаляет)

| # | Баг | Practicum аналог | Чем отличается |
|---|-----|------------------|----------------|
| B5 | **DELETE /stores — удаляет магазин с активными заказами** | Practicum: DELETE не удаляет совсем | Здесь: удаляет, хотя есть активные заказы (каскадное удаление потеряно) |
| B6 | **PATCH /cart — quantity > stock → всё равно проходит** | Practicum: DELETE не удаляет | Здесь: можно добавить больше, чем есть на складе |
| B7 | **POST /orders — заказ пустой корзины → 201** | Practicum: DELETE не удаляет | Здесь: оформить заказ без товаров |
| B8 | **POST /orders — без авторизации → 201** | Practicum: 200 с пустым телом | Здесь: любой может оформить без ключа |

### Категория: Ответ (как в Practicum — id удаляется)

| # | Баг | Practicum аналог | Чем отличается |
|---|-----|------------------|----------------|
| B9 | **GET /orders — total_cost = null** | Practicum: PATCH удаляет id | Здесь: сумма заказа null вместо 0 |
| B10 | **POST /cart — не возвращает id созданной позиции** | Practicum: PATCH удаляет id | Здесь: ответ приходит без id, хотя позиция создана |
| B11 | **PATCH /stores — возвращает старые данные после обновления** | Practicum: PATCH no id in response | Здесь: ответ содержит данные ДО обновления |
| B12 | **GET /stores/:id — возвращает 200 для несуществующего id** | Practicum: 500 при отрицательном limit | Здесь: 200 с пустым объектом вместо 404 |

### Категория: Фильтры (как в Practicum — status filter case-sensitive)

| # | Баг | Practicum аналог | Чем отличается |
|---|-----|------------------|----------------|
| B13 | **GET /stores?type=fast_food — игнорирует регистр** | Practicum: status filter case-sensitive | Здесь: регистр не важен, но возвращает неверные магазины |
| B14 | **GET /orders?status=pending — возвращает не только pending** | Practicum: filter limit ignored | Здесь: статус игнорируется, возвращаются все заказы |
| B15 | **PATCH /orders/:id/cancel — отменяет уже отменённый (всегда success)** | Practicum: success:true при ошибке | Здесь: всегда {success:true} |
