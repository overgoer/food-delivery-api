# Food Delivery API — тренажёр для контента

> **Назначение:** Демо-API для YouTube/Instagram контента.
> Не дублирует Practicum, но содержит похожие баги — на других кейсах и сущностях.
>
> **Тема:** Доставка продуктов/еды.
> **Порт (план):** 3003 на Amsterdam (локально).
> **Стек:** Node.js + Express + SQLite (без клиентских данных).
> **Версии:** v1 (баги) / v2 (фиксы).

---

## Сущности и эндпоинты

### 1. Рестораны (`/stores`)

| Метод | Эндпоинт | Описание |
|-------|----------|----------|
| GET | `/stores` | Список магазинов (+ фильтры по `type`, `city`) |
| GET | `/stores/:id` | Детально магазин + меню |
| POST | `/stores` | Добавить магазин |
| PATCH | `/stores/:id` | Обновить данные магазина |
| DELETE | `/stores/:id` | Удалить (логика: можно удалить даже с активными заказами — **баг**) |

### 2. Товары (`/products`)

| Метод | Эндпоинт | Описание |
|-------|----------|----------|
| GET | `/stores/:id/products` | Товары магазина (+ фильтр по `category`) |
| POST | `/stores/:id/products` | Добавить товар в меню |
| PATCH | `/products/:id` | Изменить цену/описание/название |
| DELETE | `/products/:id` | Убрать товар |

### 3. Корзина (`/cart`)

| Метод | Эндпоинт | Описание |
|-------|----------|----------|
| GET | `/cart` | Моя корзина |
| POST | `/cart` | Добавить товар (+ `quantity`) |
| PATCH | `/cart/:item` | Изменить количество |
| DELETE | `/cart/:item` | Удалить позицию из корзины |

### 4. Заказы (`/orders`)

| Метод | Эндпоинт | Описание |
|-------|----------|----------|
| POST | `/orders` | Оформить заказ (из корзины, адрес доставки) |
| GET | `/orders` | Мои заказы (+ статус, фильтр по `status`) |
| GET | `/orders/:id` | Детали заказа |
| PATCH | `/orders/:id/cancel` | Отменить заказ (если статус `pending`) |

### 5. Доставка (`/delivery`)

| Метод | Эндпоинт | Описание |
|-------|----------|----------|
| GET | `/orders/:id/delivery` | Статус доставки (+ курьер) |
| PATCH | `/orders/:id/delivery/assign` | Назначить курьера |

## Баги (v1)

### Валидация

| # | Баг | Суть |
|---|-----|------|
| B1 | **POST /orders — пустой адрес проходит** | Адрес `delivery_address` не проверяется, заказ уходит с пустым адресом |
| B2 | **POST /cart — quantity = -1 → успех** | Отрицательное количество, сумма уходит в минус |
| B3 | **POST /stores — пустое название магазина** | `name` может быть пустой строкой, магазин создаётся |
| B4 | **PATCH /products — цена = 0 → 200 OK** | Бесплатный товар, цена 0 не отсекается |

### Логика

| # | Баг | Суть |
|---|-----|------|
| B5 | **DELETE /stores — удаляет с активными заказами** | Не проверяет, есть ли активные заказы — каскадное удаление |
| B6 | **PATCH /cart — quantity > stock** | Можно добавить больше, чем есть на складе |
| B7 | **POST /orders — пустая корзина → 201** | Заказ без товаров успешно оформляется |
| B8 | **POST /orders — без авторизации → 201** | Любой может оформить без ключа (намеренно: id пользователя из тела) |
| B9 | **GET /orders — просмотр чужих заказов** | Нет привязки к пользователю — можно смотреть любые заказы |

### Ответ

| # | Баг | Суть |
|---|-----|------|
| B10 | **GET /orders — total_cost = null** | Сумма заказа null вместо 0 |
| B11 | **POST /cart — не возвращает id** | Ответ без id созданной позиции |
| B12 | **PATCH /stores — возвращает старые данные** | Ответ содержит ДО-обновления данные |
| B13 | **GET /stores/:id — 200 для несуществующего id** | Пустой объект вместо 404 |

### Фильтры и статусы

| # | Баг | Суть |
|---|-----|------|
| B14 | **GET /stores?type= — нечувствительность к регистру** | Тип магазина фильтруется неверно при изменении регистра |
| B15 | **GET /orders?status=pending — игнорирует статус** | Возвращает все заказы, статус не учитывается |
| B16 | **PATCH /orders/:id/cancel — отмена уже отменённого** | Всегда `{success:true}`, можно отменить повторно |
| B17 | **POST /login — кука без httpOnly** | `user_token` доступна из JavaScript — XSS-риск |
| B18 | **Пароли в БД открытым текстом** | Таблица `users` хранит пароли без хэширования |
| B19 | **POST /logout — сессия остаётся в БД** | Кука чистится, но `user_token` продолжает работать через заголовок |

## Документация

Документация в стиле продакшн-API — Swagger UI с OpenAPI спецификацией v2.

**Локально:** `http://localhost:3004/docs`
**В репозитории:** `docs/openapi.yaml`

Каждая ручка содержит SQL-запросы, которые выполняются при работе с БД.
Описано идеальное поведение API (v2) — все баги v1 исправлены.

## Установка и запуск

```bash
git clone git@github.com:overgoer/food-delivery-api.git
cd food-delivery-api
npm install
npm run dev     # v1 (c багами) — порт 3003
npm run dev:v2  # v2 (исправленная версия) — порт 3004
```

## Вход по кукам (v1)

Демо-пользователи: `alice / password123`, `bob / password123`.

```bash
curl -c cookies.txt -X POST http://localhost:3003/login \
  -H 'Content-Type: application/json' \
  -d '{"username":"alice","password":"password123"}'

curl -b cookies.txt http://localhost:3003/orders   # кука вместо X-API-Key
```

Страница входа для браузера: `GET /login`.
Для демо Interceptor: залогинься в браузере → кука `user_token` улетает в Postman через Postman Interceptor.
